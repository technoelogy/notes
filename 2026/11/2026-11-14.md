## Thread 1 — ClearRx (voice-first prescription capture)

Locked the delivery design and froze the data schema before writing a line of code.

### What I did
- Ran the reuse audit against my shipped tools. Landed at ~64% reuse: Supabase and n8n infra from MR Field Companion, the "structure to JSON" pattern from Label Lens, plus my n8n-import-SOP and Builder's SOP for method.
- Killed one reuse idea on purpose. Using Label Lens OCR as a handwriting sanity-check would reintroduce the exact failure it taught me (vision models garble Indian packs). Voice-first exists to route around handwriting, so the OCR cross-check is out.
- Mapped how the finished Rx reaches the patient. Three rails, all rendered off one record: print, WhatsApp image, database row.

### What I learned
- WhatsApp has a real gate. A wa.me text link cannot carry a file, and the Business API needs Meta verification plus template approval. Not a 7-day path, so it moves to Phase 2.
- The printer is the unlock. Zero-gate rail: the browser print dialog off a print stylesheet, no API, no cost. In an Indian OPD the printed Rx is what the patient expects anyway.
- The sharpest lesson came from my own behaviour. When I refill my meds I open the prescription pic in my WhatsApp gallery, not a link. Patients want an image that opens offline, forever. So v1 renders the Rx as a PNG and shares it via the Web Share API into WhatsApp. No Business API needed.
- Capture structured data at the source. The Rx JSON is the single source of truth, and print, image, database, and a future EHR export are all renderings of it. Normalising drug names to RxNorm is what makes the record queryable, not just stored.

### Decision locked
Froze the Rx schema contract v1.0 before P1. Every downstream piece renders against a stable shape instead of a moving target. FHIR-ready fields sit null for now so the EHR build later is a transform, not a rebuild.

### Next
P1 (14-16 Nov): scaffold the folder per Builder's SOP, then stub Wispr capture → Claude structuring → valid JSON with one hard-coded drug. Highest-risk integration, so prove it first.

## Thread 2 — Scaler x Wispr "Build for Bharat" hackathon, Round 1 Activity 02

Wrote the prompt I'd hand an AI app builder to prototype the idea. Mine is ASHA Awaaz, voice-first visit logging for India's ASHA workers, local language in and structured PHC data out.

What I took away: a build prompt is not a pitch. The rubric weights the voice flow heaviest, then how you handle things going wrong, then how buildable it is. So you spec the conversation turn by turn, what the ASHA says and what the app says back at each step, instead of selling the vision. I scripted five steps around a real visit narrative, a pregnant woman missing her iron tablets, then five failure modes: background noise, a Bhojpuri speaker using Hindi words, mid-sentence code-switching, misheard fields, and no network.

One call I made: left the research citations out of the prompt. They earn their keep in an idea submission, not in a build spec that gets scored on reproducibility.
